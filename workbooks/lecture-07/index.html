Lecture summary

A playlist can visit every track, stop at the first matching title, or remove matching tracks as it goes. The class below shows the search and removal patterns. It uses the lecture's Track class and assumes stored tracks, titles, and artists are non-null.

import java.util.ArrayList;
import java.util.Iterator;

public class Playlist
{
    private ArrayList<Track> tracks;

    public Playlist()
    {
        tracks = new ArrayList<>();
    }

    public void addTrack(Track track)
    {
        tracks.add(track);
    }

    public int findFirstTrackIndex(String title)
    {
        int index = 0;
        boolean found = false;
        while(index < tracks.size() && !found) { // bounds and search status
            Track track = tracks.get(index);
            if(track.getTitle().equals(title)) { // compare text
                found = true;
            }
            else {
                index++;                       // no match: check the next track
            }
        }
        if(found) {
            return index;
        }
        return -1;                             // no matching position
    }

    public Track findFirstTrack(String title)
    {
        int index = findFirstTrackIndex(title);
        if(index == -1) {                       // check before get
            return null;
        }
        return tracks.get(index);
    }

    public void removeTracksByArtist(String artist)
    {
        Iterator<Track> iterator = tracks.iterator();
        while(iterator.hasNext()) {
            Track track = iterator.next();     // return a track and advance
            if(track.getArtist().equals(artist)) {
                iterator.remove();             // remove that track safely
            }
        }
    }
}

In this workbook, assume stored tracks, titles and artists are never null. Lecture 6 used for-each to print every track, or every track that matches a condition. For-each is the clearest loop when every element should be visited. It has three limits: it does not give you the index, it is a poor choice for stopping at the first match, and you must not remove elements through the list while it runs. This lecture covers a loop for each of those jobs.

Definite and indefinite iteration

Definite iteration processes a set of elements that is known when the loop starts. For-each over a playlist is the usual example: it visits every current track once.

Indefinite iteration continues until a condition changes. Searching for the first track with a given title is indefinite, because at the start we do not know where a match will stop the loop. A failed search may visit every element, but it is still indefinite.

The while loop

A while loop repeats its body while a boolean condition is true:

while(booleanCondition) {
    // statements to repeat
}

The condition is tested before every pass, including the first one. If it is false on the first test, the body runs zero times. The body must make progress towards a false condition; otherwise the loop never stops. A while loop needs no collection. It can count, or keep asking until some input is valid.

Walk a list by index

An indexed while loop manages the position itself. This example prints every name in an ArrayList<String> called names, with its index:

int i = 0;
while(i < names.size()) {
    String name = names.get(i);
    System.out.println(i + ": " + name);
    i++;
}

2. Search

A search has two ways to finish

A first-match search stops when it finds a match, or when it has checked every element without one. It needs two variables: an int for the current position and a boolean that records whether a match has been found.

  1. Start with index at 0 and found false.
  2. While the index is valid and nothing has been found, get the element at index. If it matches, set found to true. Otherwise, add 1 to index.
  3. After the loop, return index if found is true, and -1 otherwise.

The loop condition is index < tracks.size() && !found. The operator && is true only when both sides are true. Java tests it from left to right and stops early: if the index is no longer valid, the right side is not evaluated.

The update happens only after a non-match. On a match, the index must stay at the matching position so the method can return it. On every pass either the index moves forward or the flag changes, so the loop always makes progress.

Successful and failed searches

Search [Northern Sky, Blue Train, Teardrop, Teardrop] for "Teardrop". The loop checks three titles and stops with the index at 2. The second Teardrop is never checked, because the search wants only the first match. A match at index 0 takes a single check.

When there is no match, every title is checked and the index reaches the size of the list. The condition index < tracks.size() becomes false, so the loop stops without calling get on an invalid index. Do not force the index past the end to stop a loop; let the condition do it.

The same control can be written with a flag named searching that starts at true. The condition becomes index < tracks.size() && searching, and a match sets searching to false. Choose whichever name reads more clearly.

Identity is not the same as equality

For object references, a == b asks whether both variables refer to the same object. The call a.equals(b) asks whether two strings contain the same characters. Two different String objects can hold the same text.

Java reuses one object for equal string literals written in quotes in the code, so == can seem to work in a small test. Text that is built or read while the program runs need not share an object, and then == gives false. Always use equals to compare string contents.

Use a returned index safely

The value -1 is outside the range of valid indexes, so it can mean "not found". A special value like this is called a sentinel value. The caller must check the result before using it as a position. The Playlist method getTrack(index) simply returns tracks.get(index), so getTrack(-1) throws an IndexOutOfBoundsException.

4. Iterator

An iterator is a traversal object

An Iterator is an object that remembers how far a traversal has moved through a collection. Import the type, then ask the list for one:

import java.util.Iterator;

Iterator<String> iterator = names.iterator();

Watch the capital letters: Iterator is a type, and iterator() is a method of the list. The type parameter, here String, says what kind of element the iterator returns. Two methods control an ordinary traversal:

MethodMeaning
hasNext()Returns whether another element is available. It does not move the iterator.
next()Returns the next element and moves past it.

This loop prints every name:

Iterator<String> iterator = names.iterator();
while(iterator.hasNext()) {
    String name = iterator.next();
    System.out.println(name);
}

Call next() only when hasNext() is true. After the last element, hasNext() returns false, and another next() throws a NoSuchElementException. An iterator moves forward only; it cannot go back to an earlier element.

An iterator also works for collections that have no index, so the same pattern is used across the Java collection library. A for-each loop uses an iterator behind the scenes, but it does not let you call that iterator's methods.

5. Removal

Do not remove through the list inside for-each

This code looks reasonable but is wrong:

for(String name : names) {
    if(name.length() < 4) {
        names.remove(name);
    }
}

The for-each loop keeps its own hidden position. Removing through names changes the list without telling that hidden iterator, and the loop can then throw a ConcurrentModificationException. The exception does not happen in every case, so one run without it proves nothing.

Indexed removal can skip an element

When an indexed loop removes the element at index i, every later element shifts one place to the left. The element that moves into index i has not been checked yet. If the loop then adds 1 to i, that element is skipped. The loop can be repaired, by adding 1 only when nothing was removed, but it needs care.

Use the iterator to remove its current element

The iterator's remove() method deletes the element returned by the most recent next(). This loop removes every name shorter than four letters:

Iterator<String> iterator = names.iterator();
while(iterator.hasNext()) {
    String name = iterator.next();
    if(name.length() < 4) {
        iterator.remove();
    }
}

The order matters: check with hasNext(), obtain the element with next(), decide whether it should go, and only then call iterator.remove(). Because the iterator makes the change itself, it stays in step with the list, and adjacent matches are not skipped. Call remove() at most once for each next(), and never before the first next(); otherwise it throws an IllegalStateException. In Lecture 8 you will see a shorter way to remove matching elements.

6. References

Null means no object

A method with return type Track normally returns a reference to a Track object. When a lookup fails, it can return null instead. null is not an empty Track; it means there is no object at all. A -1 cannot be returned here, because the return type is Track, not int.

The caller must test the result with != null before calling a method on it. Calling a method through null throws a NullPointerException: the variable exists, but there is no object for the method to run on. Comparing with null checks whether there is a reference; it does not compare string contents.

A field of a reference type that is never assigned holds null by default. So if a constructor forgets tracks = new ArrayList<>();, the first tracks.size() throws a NullPointerException. An empty list is different: it is a real object, and its size() returns 0. A local variable gets no default; the compiler rejects code that reads it before it is assigned.

References inside references

A Playlist object holds a reference to an ArrayList. The list holds references to Track objects, and each track holds references to its title and artist String objects. Following Playlist, then ArrayList, then Track, then String means following one reference at each step, and every step must lead to a real object.

Anonymous objects and chained calls

An object can be created directly as an argument, without a local variable:

schedule.addAppointment(new Appointment("Ana"));

This is an anonymous object: no variable names the new reference. The object is not lost, because the method that receives it can store the reference, as a list does. Keep a named local variable instead when you will use the reference again, or when the name makes the code easier to read.

A method that returns an object can be followed by another call on that object. Read such a chain from left to right, and note the type each call returns. In playlist.getTrack(0).getTitle(), the first call returns a Track, and getTitle() runs on that track and returns a String. A chain is safe only when every call returns a real object and every index is valid, here index 0. If a call in a chain may return null, store its result in a variable, test it, and only then call the next method.

  • CourseRoster stores an ArrayList<Student>. Give it a constructor and these methods: enrol(Student student); printAllStudents(), which uses for-each; and removeStudentsFromProgram(String program), which uses an iterator and removes every match, including adjacent ones.
  • CourseRosterDemo enrols Amina (Computer Science), Diego (Mathematics), Hana (Mathematics) and Linh (Business), in that order. It prints Before removal: and the roster, removes the Mathematics students, then prints After removal: and the roster again. Diego and Hana are adjacent, so the demo shows that no match is skipped.
