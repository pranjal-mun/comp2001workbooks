Lecture summary

A playlist can visit every track, stop at the first matching title, or remove matching tracks as it goes. The class below shows the search and removal patterns. It uses the lecture's Track class and assumes stored tracks, titles, and artists are non-null.

import java.util.ArrayList;
import java.util.Iterator;

public class Playlist
{
    private ArrayList<Track> tracks;

    public Playlist()
    {
        tracks = new ArrayList<>();
    }

    public void addTrack(Track track)
    {
        tracks.add(track);
    }

    public int findFirstTrackIndex(String title)
    {
        int index = 0;
        boolean found = false;
        while(index < tracks.size() && !found) { // bounds and search status
            Track track = tracks.get(index);
            if(track.getTitle().equals(title)) { // compare text
                found = true;
            }
            else {
                index++;                       // no match: check the next track
            }
        }
        if(found) {
            return index;
        }
        return -1;                             // no matching position
    }

    public Track findFirstTrack(String title)
    {
        int index = findFirstTrackIndex(title);
        if(index == -1) {                       // check before get
            return null;
        }
        return tracks.get(index);
    }

    public void removeTracksByArtist(String artist)
    {
        Iterator<Track> iterator = tracks.iterator();
        while(iterator.hasNext()) {
            Track track = iterator.next();     // return a track and advance
            if(track.getArtist().equals(artist)) {
                iterator.remove();             // remove that track safely
            }
        }
    }
}
termmeaning
definite and indefinite iterationDefinite iteration processes a known set, such as every track with for-each. A search is indefinite because a match can stop it early. A failed search may still visit the whole list.
while and indexed traversalA while tests its condition before each pass, so its body may run zero times. Indexed traversal starts at 0, tests index < tracks.size(), retrieves with get(index), and updates the index. Missing progress can cause an infinite loop. A while loop need not involve a collection.
first-match searchContinue while the index is valid and !found. A match sets found to true; otherwise increment the index. Keep position and search status separate. Stop on success or exhaustion, including an empty list.
equals and ==For objects, == compares references. String.equals compares text. Java shares equal string literals, which can make an incorrect == comparison appear to work.
sentinel-1 means no matching index; 0 is a valid match. Check the result before calling get. Passing -1 to get throws IndexOutOfBoundsException.
iteratortracks.iterator() supplies an object that remembers traversal state. hasNext() checks without advancing; next() returns an element and advances. Calling next() after exhaustion throws NoSuchElementException.
removal during traversalRemoving through the list during for-each can cause ConcurrentModificationException. In an index loop, removing B from [A, B, C, D] shifts C left; incrementing the index then skips C. Use iterator.remove() to remove the most recently returned element, at most once after each next(). The iterator stays in step with the list.
nullnull means no object. Reference fields default to null; local variables need an assignment before use. A lookup may return null, so test result != null before result.printDetails(). A method call through null throws NullPointerException.
anonymous objectplaylist.addTrack(new Track("So What", "Miles Davis", 545)); passes a new object directly, without a local variable. The list keeps its reference.
chained callsRead track.getTitle().length() left to right: getTitle() returns a String, then length() returns an int. Each call uses the previous result. A chain such as playlist.findFirstTrack(title).printDetails() is unsafe if the lookup returns null; store and check that result first.
