Object Orientation

Why programs outgrew parallel lists, and the ideas that object-oriented languages brought.

Computing in 1960

Computers
  • Computers filled rooms and cost a fortune.
  • Universities and large organizations shared one machine.
  • Processing happened in scheduled batch runs.
Programming
  • Programs often arrived as punched cards.
  • A small mistake could mean another batch run.
  • FORTRAN, COBOL, ALGOL, and Lisp were still young.

Procedural Ship Simulation

names = ["Oliver", "Sabina"]
positions = [42, 7]
speeds = [12, 6]
fuel = [81, 65]

def move(ship_index):
    positions[ship_index] += speeds[ship_index]
    fuel[ship_index] -= 1

move(0)
print(names[0], positions[0], fuel[0])

The four lists must stay in the same order. Index 0 means Oliver everywhere.

The Software Crisis

Programs grew faster than teams learned to manage them.

In 1968, a NATO conference in Garmisch put software engineering in its title.

Large projects exposed recurring problems:

  • schedules slipped,
  • costs grew,
  • changes broke distant parts of the program,
  • no one person understood the whole system.

The field needed ways to divide a program so people could reason about one part at a time.

Simula 67

Ole-Johan Dahl and Kristen Nygaard developed Simula at the Norwegian Computing Center.

They were building simulations of systems with many independent parts. Examples include ships in a harbour, customers in a queue, and machines in a factory.

The old approach scattered each thing across several arrays. Simula let a programmer describe one kind of thing, then create many individual examples of it.

  • Simula 67 introduced classes, objects, inheritance, and virtual methods.
  • Dahl and Nygaard received the 2001 Turing Award for this work.

Classes and Objects

The class Ship describes what every ship has and what every ship can do: position, speed and fuel, and move() and load(). The objects ship37 and ship38 are made from it.

ship37.move() changes the position stored inside ship37. It does not change ship38.

Class and object

A class is a definition. An object is one particular instance made from it.

Object-Oriented Ship Simulation

class Ship:
    def __init__(self, name, position, speed, fuel):
        self.name = name
        self.position = position
        self.speed = speed
        self.fuel = fuel
    def move(self):
        self.position += self.speed
        self.fuel -= 1

oliver = Ship("Oliver", 42, 12, 81)
sabina = Ship("Sabina", 7, 6, 65)
oliver.move()
print(oliver.position, oliver.fuel)

Each object keeps one ship's data together. move() changes the receiver.

Smalltalk

Alan Kay and the Learning Research Group developed Smalltalk at Xerox PARC in the 1970s.

Simula used objects to model a simulation. Smalltalk applied the object idea throughout the language and its programming environment.

  • Numbers, text, windows, and buttons are objects.
  • A programmer works with live objects and can change a program while it runs.
  • The team designed Smalltalk partly for children learning through computers.

This work helped establish the style of graphical programming environments that later became familiar on personal computers.

Messages in Smalltalk

Smalltalk reads the familiar expression 3 + 4 as a message:

  • receiver: 3
  • message: +
  • argument: 4

Other messages:

button clickAsk a button to respond.
ship moveAsk a ship to move.
account deposit: 20Ask an account to deposit 20.

The sender asks for an operation. The receiving object decides how to carry it out.

Four OOP Ideas

IdeaProblem it addresses
Encapsulation
Keep state with its methods.		Any part of the program could change shared data.
Abstraction
Expose a small interface.		A programmer had to understand every implementation detail.
Inheritance
Build a specific class from a general one.		Closely related classes repeated common code.
Polymorphism
Use one request for several types.		Adding a new kind required edits throughout the program.
An object

An object knows something, can do something, and controls access to its state.

Early Object-Oriented Languages

  • 1967 Simula 67: classes, objects, and inheritance
  • 1979 C with Classes: Simula-style organization added to C
  • 1980 Smalltalk-80: a complete object-oriented environment
  • 1985 C++: C with object-oriented language features

Simula proved the idea. Smalltalk built a complete environment around it.

Bjarne Stroustrup combined Simula-style program organization with the efficiency and practical reach of C.

Graphical Interfaces and OOP

A natural fit

A window has state and behaviour. So do buttons, menus, scrollbars, and documents.

Graphical software gave object orientation a natural, visible use.

Mainstream adoption

By the 1990s, C++, Smalltalk, design patterns, and object diagrams had carried OOP into mainstream development.

Object Orientation Today

What remains useful
  • Keep related state and behaviour together.
  • Protect decisions that may change.
  • Give each part of a program a clear responsibility.
  • Program through small, stable interfaces.
What modern practice adds
  • Composition often gives more flexibility than deep inheritance.
  • Immutable data can remove whole classes of bugs.
  • Functional operations can express data processing clearly.
  • Different problems deserve different styles.

Modern Java uses objects for structure and also includes functional tools for processing data.

Java

Where Java came from, how the Java platform runs a program, and where Java is today.

Computing in 1991

A new market

The World Wide Web was new.

Companies expected televisions, organizers, and appliances to become interactive.

A portability problem

Each device family had its own processor and operating system.

A program written for one device might need major changes before it could run on another.

Memory and Portability

Manual memory management

In C and C++, programmers allocate memory and release it themselves.

Common failures include:

  • forgetting to release memory,
  • using memory after release,
  • writing past an array boundary.
Native binaries

A compiler normally produces instructions for one processor and operating system.

Another device needs another build, more testing, and often more platform-specific code.

The Green project wanted reliable software that could survive a changing device market.

The Green Project

The team

In 1991, James Gosling, Mike Sheridan, Patrick Naughton, and colleagues at Sun started the Green project.

Gosling created a language called Oak for networked consumer devices.

Design goals
  • portable programs
  • automatic memory management
  • checked array access
  • a smaller language than C++

Java and the Web

Early 1990sThe consumer electronics business did not take off as Sun expected.
The webPortable, network-delivered code suddenly had an obvious use.
1995Sun renamed Oak to Java and announced it publicly.
HotJavaSun's browser demonstrated programs running inside web pages.

The Java Platform

Compilejavac Hello.java
Runjava Hello

The same class file can run on any compatible Java Virtual Machine.

Java's Growth

  • 1995 to 1996 Web debut and JDK 1.0
  • 1998 Java 2 and the Collections Framework
  • 2000s Server software and large business systems
  • 2008 onward Android applications
  • 2010 onward Oracle stewardship and regular releases

Applets drew attention first, then disappeared. Java kept growing through server software, large business systems, developer tools, and Android.

The 1998 Collections Framework introduced familiar classes such as ArrayList.

Java Today

The platform in 2026
  • JDK 26 is the current feature release.
  • JDK 25 is the current long-term support release.
  • A new feature release arrives every six months.
  • The JVM also hosts Kotlin, Scala, and Clojure.
Modern language features
  • Lambdas and streams
  • Records
  • Pattern matching
  • Virtual threads

Java continues to serve long-lived systems where compatibility and clear structure matter.
