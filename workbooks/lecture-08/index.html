Lecture summary

A lambda lets us pass code for one track to a collection method. In this example, Playlist stores Track references, forEach runs the printing action, and removeIf uses a boolean test to remove matches. The class and table cover the lecture; use them for a quick review before a test.

import java.util.ArrayList;

public class Playlist
{
    private ArrayList<Track> tracks;

    public Playlist()
    {
        tracks = new ArrayList<Track>();
    }

    public void addTrack(Track track)
    {
        tracks.add(track);
    }

    public void printAllTracksWithLoop()
    {
        for(Track track : tracks) {      // External iteration: we write the loop.
            track.printDetails();
        }
    }

    public void printAllTracks()
    {
        // Four alternative lambdas for the same action:
        // 1. (Track track) -> { track.printDetails(); }
        // 2. (track) -> { track.printDetails(); }
        // 3. track -> { track.printDetails(); }
        // 4. track -> track.printDetails()
        tracks.forEach(track -> track.printDetails());
        // Internal iteration: forEach supplies each track.
    }

    public void printAllTracksWithReference()
    {
        tracks.forEach(Track::printDetails); // Same action, existing method.
    }

    public void removeTracksByArtist(String artist)
    {
        tracks.removeIf(track -> track.getArtist().equals(artist));
    }

    public void reportShortTrackRemovals()
    {
        int before = tracks.size();
        boolean changed = tracks.removeIf(
            track -> track.getDurationSeconds() < 300);
        int removed = before - tracks.size();
        System.out.println(changed);    // Whether any track was removed.
        System.out.println(removed);    // How many tracks were removed.
    }
}

2. Lambdas

Code as an argument

So far, every argument has been data: a number such as the 2 in getTrack(2), or a reference such as the track in addTrack(track). A lambda is a piece of code that can be stored and passed to a method as an argument. The method that receives it decides when to run it, how many times, and what argument to give it each time. Writing a lambda does not run its body, in the same way that writing a method does not call it.

From a method to a lambda

Compare a small method with the lambda that does the same job:

public void printTrack(Track track)
{
    track.printDetails();
}
(Track track) -> { track.printDetails(); }

The lambda drops the access modifier, the return type and the name. Java works out the result type from the body. Because it has no name, a lambda is also called an anonymous function. It keeps the parameter list and the body, and puts an arrow between them. A lambda is not a class: it has no fields and no constructor. A job that needs to remember its own state between calls still needs a class.

Lambda parts

(Track track) -> { System.out.println(track.getTitle()); }
PartMeaning
(Track track)The parameter list: one track to work on.
->The arrow separates the parameters from the body.
{ System.out.println(...); }The body: the code to run for that track.

The lambda declares track itself, just as a method declares its parameters, so no earlier declaration is needed. The name is our choice; t or song would work too. The arrow does not mean "return". This body prints, and returns nothing.

3. forEach

The forEach method

Every ArrayList has a method forEach. Its one argument is an action: a lambda that takes one element. forEach runs the action once for each element, in list order, and passes the element in as the argument. These two versions of printAllTracks print the same output:

public void printAllTracks()
{
    for(Track track : tracks) {
        track.printDetails();
    }
}
public void printAllTracks()
{
    tracks.forEach((Track track) -> {
        track.printDetails();
    });
}

The (Track track) -> { ... } part is the lambda. The final ); closes the call to forEach.

External and internal iteration

In the first version, our code runs the loop and asks the list for each element in turn. This is external iteration, the usual imperative style. In the second version, the loop is inside forEach; our code supplies only the action. This is internal iteration, the style of functional programming. The loop has not disappeared. It has moved into the list's method, which we did not write.

One call per element

With the five tracks, forEach calls the lambda five times. The first call receives a reference to Northern Sky, the second a reference to Blue Train, and so on. The lambda receives the element itself, not its index. With an empty list, the lambda is called zero times and forEach finishes normally.

forEach returns nothing. A forEach call can print every title, but it cannot give back a list of titles or a total. The action may call methods that change the element, such as a mutator. It must not add elements to, or remove elements from, the same list while forEach is running; Section 7 shows what goes wrong.

4. Syntax

Four stages

The lambdas so far were written out in full. Java lets us leave parts out when it can work them out. Each stage below makes one omission from the stage before; all four mean the same thing as an argument to tracks.forEach(...):

// Stage 1: everything written
(Track track) -> { track.printDetails(); }
// Stage 2: omit the parameter type
(track) -> { track.printDetails(); }
// Stage 3: omit the parameter parentheses
track -> { track.printDetails(); }
// Stage 4: use an expression body
track -> track.printDetails()
OmissionWhy it is allowed
Parameter typetracks is an ArrayList<Track>, so Java already knows each element is a Track.
ParenthesesThere is exactly one parameter and its type is not written. Keep them for zero parameters, two or more, or a written type.
Braces and ;The body is a single expression. Java uses its value, if it has one, as the result.

So (Track track) and (track) are valid, but Track track -> ... is not. In a complete statement the last stage reads tracks.forEach(track -> track.printDetails());. The final ; ends the forEach call, not the lambda.

A body with two or more statements must keep its braces and the semicolon after each statement. Only the type and the parentheses can go. To read a short lambda, put the parts back in reverse order: braces and semicolon, then parentheses, then the type.

Method references

When a lambda does nothing except call one existing method, a method reference can replace it. It names the class and the method, separated by ::, with no parentheses after the method name:

tracks.forEach(track -> track.printDetails());
tracks.forEach(Track::printDetails);

Here forEach supplies each track, and printDetails() is called on that track. A method reference can also pass the element as an argument. If titles is an ArrayList<String>, these two lines print every title:

titles.forEach(title -> System.out.println(title));
titles.forEach(System.out::println);

Here each title is passed to println, which is called on the object System.out. Writing a method reference does not call the method, just as writing a lambda does not run its body. The method must match the job: tracks.forEach(System.out::println) compiles, but it passes each Track object to println, which prints text such as Track@1b6d3586 rather than the track's details.

6. Predicates

Actions and tests

A lambda can do one of two kinds of job. An action does something with an element and gives nothing back, like track -> track.printDetails(). A test answers a yes-or-no question about an element, like track -> track.getDurationSeconds() < 300.

The method that receives the lambda decides which kind it needs. forEach needs an action. removeIf, in Section 7, needs a test. If we pass the wrong kind, the code does not compile: tracks.removeIf(track -> track.printDetails()) fails because printDetails() gives no boolean answer. In the Java library these shapes are called functional interfaces; you do not need to write their names in this course.

Predicates

A test of one element that returns true or false is called a predicate. With an expression body, the boolean expression is the answer, so no if and no return are needed. Applied to the five tracks, track -> track.getDurationSeconds() < 300 gives true for Northern Sky (224) and Naima (265), and false for the other three. A track of exactly 300 seconds would give false, because < is strict. A predicate only reads the track; it does not change or remove it.

Predicate expressions

Any boolean expression about the parameter can be the body:

track -> track.getArtist().equals("Nick Drake")
track -> track.getTitle().contains("Sky")
track -> track.getDurationSeconds() >= 330
track -> true

Use equals to compare text; == compares references, as in Lecture 7. The String method contains returns true if the given text appears anywhere in the string. The constant predicate track -> true accepts every track, and track -> false accepts none. Combine conditions with && and ||. A block body is allowed, but then it must return the answer: track -> { return track.getDurationSeconds() < 300; }.

7. Removal

The removeIf method

removeIf takes a predicate. It runs the predicate once for each element. When the answer is true it removes that element; when it is false it keeps it. Every match is removed, including matches that sit next to each other, so it never skips an element the way the indexed loop in Lecture 7 could. The remaining elements keep their order and move to lower indexes. The call changes the existing list; it does not make a new one.

removeIf also returns a boolean: true if it removed at least one element, false if the list did not change. The predicate answers for one element; the return value answers for the whole call.

Removal by artist

Lecture 7 removed every track by an artist with an iterator. With removeIf, the list does the traversal and the removal, and we supply only the test:

public void removeTracksByArtist(String artist)
{
    tracks.removeIf(track -> track.getArtist().equals(artist));
}

The lambda can use the parameter artist of the surrounding method. If no other method in the class uses Iterator, delete import java.util.Iterator;.

Counting removals

To know how many elements were removed, save the size first:

int before = tracks.size();
boolean changed = tracks.removeIf(track -> track.getDurationSeconds() < 300);
int removed = before - tracks.size();

For the five tracks, Northern Sky and Naima are removed, changed is true and removed is 2. If nothing matches, removed is 0 and changed is false.

Removal inside forEach

Lecture 7 showed that removing through the list inside a for-each loop is unsafe. The same is true inside forEach:

tracks.forEach(track -> {
    if(track.getArtist().equals("John Coltrane")) {
        tracks.remove(track);
    }
});

Changing which elements are in the list while forEach is running can throw a ConcurrentModificationException. Use removeIf instead, and do not call remove inside its predicate either. Calling a mutator on an element, such as checkIn(), is fine: it changes the element, not the list.

8. Choices

Choosing a loop

forEach and removeIf do not replace loops; they cover two common jobs.

JobUseful choice
One small action for every elementforEach, or a for-each loop
Remove every element that passes one testremoveIf
Use an index, or stop at the first matchan explicit loop, such as an indexed while
Update local variables while visitingan explicit loop

The last row has a reason. A lambda can read a local variable of the surrounding method, as the removal method in Section 7 reads artist, but only if that variable never changes after it gets its value. A lambda cannot change a local variable either, so this does not compile:

int count = 0;
tracks.forEach(track -> {
    count++;
});

A for-each loop that adds 1 to count works. Lecture 9 shows a better tool for counting and totals.

Selection inside an action

A forEach action can contain an if, so it can print only the Coltrane tracks. It still receives every track; the selection is buried inside the action. Lecture 9 separates choosing elements from what is done with them. Shorter code is not automatically clearer or faster, and this list's forEach runs one element at a time, in order.
