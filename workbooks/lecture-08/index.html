Lecture summary

A lambda lets us pass code for one track to a collection method. In this example, Playlist stores Track references, forEach runs the printing action, and removeIf uses a boolean test to remove matches. The class and table cover the lecture; use them for a quick review before a test.

import java.util.ArrayList;

public class Playlist
{
    private ArrayList<Track> tracks;

    public Playlist()
    {
        tracks = new ArrayList<Track>();
    }

    public void addTrack(Track track)
    {
        tracks.add(track);
    }

    public void printAllTracksWithLoop()
    {
        for(Track track : tracks) {      // External iteration: we write the loop.
            track.printDetails();
        }
    }

    public void printAllTracks()
    {
        // Four alternative lambdas for the same action:
        // 1. (Track track) -> { track.printDetails(); }
        // 2. (track) -> { track.printDetails(); }
        // 3. track -> { track.printDetails(); }
        // 4. track -> track.printDetails()
        tracks.forEach(track -> track.printDetails());
        // Internal iteration: forEach supplies each track.
    }

    public void printAllTracksWithReference()
    {
        tracks.forEach(Track::printDetails); // Same action, existing method.
    }

    public void removeTracksByArtist(String artist)
    {
        tracks.removeIf(track -> track.getArtist().equals(artist));
    }

    public void reportShortTrackRemovals()
    {
        int before = tracks.size();
        boolean changed = tracks.removeIf(
            track -> track.getDurationSeconds() < 300);
        int removed = before - tracks.size();
        System.out.println(changed);    // Whether any track was removed.
        System.out.println(removed);    // How many tracks were removed.
    }
}
termmeaning
lambdacode passed as an argument to a method; track is its parameter, -> separates parameters from the body, and writing the lambda does not run it
forEachruns the action once per element, in list order, and returns nothing; five tracks mean five calls, an empty list means zero
external / internal iterationa for-each loop puts repetition in our code; tracks.forEach(...) puts it inside the collection method, which supplies each track reference
four syntax stagesstart with (Track track) -> { track.printDetails(); }; omit Track, then the parameter parentheses, then use the expression body track -> track.printDetails()
parentheses and bodyomit parameter parentheses only for one parameter with no written type; an expression body has no braces or internal semicolon; two statements need braces and semicolons, and the method call still ends with ;
predicatea test that returns boolean, such as track -> track.getDurationSeconds() < 300; a block body needs return; the test alone removes nothing
removeIf and its resultremoves every element whose predicate returns true, changes the existing list, and keeps survivor order; the call returns true if anything was removed, otherwise false, including for an empty list
counting removalsbefore - tracks.size() gives the count; for the five lecture tracks and a threshold of 300 seconds, Northern Sky (224) and Naima (265) are removed: size 5 becomes 3, changed is true, and removed is 2
removal during forEachcalling tracks.remove(track) inside the action changes the list during traversal and can cause ConcurrentModificationException; use removeIf, and do not call remove inside its predicate either
method referenceTrack::printDetails replaces track -> track.printDetails(); forEach supplies the receiver; System.out::println would pass each track to println instead
