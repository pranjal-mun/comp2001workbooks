1. Read Methods

Fields store state; methods make it usable

Lecture 3 established that fields store an object's persistent state and a constructor gives those fields initial values. This workbook starts with a small class that already has those parts:

public class CampusCard
{
    private String owner;
    private int balance;
    private int totalSpent;

    public CampusCard(String owner, int openingBalance)
    {
        this.owner = owner;
        balance = openingBalance;
        totalSpent = 0;
    }
}

The values are in the object, but clients still need controlled ways to read and change them. A method defines one operation that objects of the class can perform.

A method has a header and a body

public int getBalance()
{
    return balance;
}

The header is public int getBalance(). Read it from left to right:

partmeaning
publicCode outside the class may call the method.
intThe call returns an integer result.
getBalanceThe method's name.
()The parameter list is empty.

The body is the block between the braces. It contains the declarations and statements that perform the work. Parentheses identify a method header even when the list is empty; a field declaration has no parentheses and ends with a semicolon.

2. Return Values

Accessors answer questions about state

An accessor returns information about an object without changing its state. A getter is a common accessor that returns one field directly.

public String getOwner()
{
    return owner;
}

public int getBalance()
{
    return balance;
}

The return type is a promise. getOwner promises a String; getBalance promises an int. The expression after return must produce a compatible value. Executing return sends the value to the caller and ends that method call.

The name getOwner is only a convention. The body decides what comes back: the method returns owner because its body says return owner;, not because of its name.

Returning and printing are different

return a valueprint text
return balance; sends an integer to the caller.System.out.println(balance); sends characters to the terminal.
The caller can store or calculate with the result.Printing alone gives the caller no result value.
The method has a non-void return type.A printing method may have return type void.

3. Change State

Mutators update fields

A mutator changes one or more fields, so the object's state differs after the call. A typical update reads an old field value, computes a new value, and assigns it back:

public void topUp(int amount)
{
    balance = balance + amount;
}

If balance is 1200 and amount is 300, the expression on the right evaluates to 1500. Assignment replaces the old field value with 1500. The parameter disappears when the call ends; the field retains its new value.

A setter is a basic mutator that directly replaces a field:

public void setOwner(String owner)
{
    this.owner = owner;
}

Here this.owner means the current object's field, while owner alone means the parameter. Not every field needs a setter. A behavior method such as topUp states the intended action and can protect the object's rules.

4. Make Choices

Boolean expressions control branches

The naïve topUp method accepts zero and negative values. A naïve payment may also produce a negative balance. A useful object checks a request before changing its fields.

A boolean expression has the value true or false. Common numeric comparisons are:

<<=>>===!=
lessat mostgreaterat leastequalnot equal

Assignment uses one equals sign; equality comparison uses two. The exact boundary matters: amount > 0 rejects zero, while amount >= 0 accepts it.

Use conditions to protect state

This version of topUp returns boolean instead of void, so the caller finds out whether the top-up was accepted.

public boolean topUp(int amount)
{
    if(amount > 0) {
        balance = balance + amount;
        return true;
    }
    else {
        return false;
    }
}

Exactly one branch runs. An invalid amount returns false and leaves the field unchanged.

Payment needs two requirements: the amount must be positive, and it must not exceed the balance.

public boolean pay(int amount)
{
    if(amount > 0 && amount <= balance) {
        balance = balance - amount;
        totalSpent = totalSpent + amount;
        return true;
    }
    else {
        return false;
    }
}

The operator && means both boolean conditions must be true. The method is a mutator because successful calls change fields, and it also returns a result that tells the caller whether the change occurred.

The class protects this invariant: balance >= 0. A constructor and every mutator must preserve that rule.

5. Keep It Local

Use a local variable for temporary storage

A refund must return the current balance and then clear the field. Clearing first loses the old value. The demo behind this box refunds a card with balance 1200 and prints what came back:

Returning first does not work either because return ends the method; code after it is unreachable, and the compiler says so.

A local variable keeps the old value while the field is cleared:

amountToRefund is a local variable. It is declared inside the method, stores temporary work, has no visibility modifier, and is recreated for each call. Local variables receive no default value; a local must be assigned before its value is used.

Fields, parameters, and locals have different jobs

kindwhere declared and usedhow long it lives
fieldin the class, outside methods; usable throughout the classas long as the object
parameterin a method or constructor headerone call
localinside a block; usable only in that blockwhile that block executes

Scope is the textual region where a name can be used. Lifetime is how long its variable exists at run time. Prefer the narrowest scope that fits the value's purpose. A value needed only while one method runs should usually be local, not a field.

Nested blocks create smaller scopes

// Fragment: the return statements are left out to keep the example short.
public boolean pay(int amount)
{
    if(amount > 0 && amount <= balance) {
        int oldBalance = balance;
        balance = balance - amount;
    }
    // oldBalance is not in scope here.
}

balance is in scope throughout the class. amount is in scope throughout the method. oldBalance is in scope only in the if block, from its declaration onward. Indentation shows the structure, but braces define it.

6. Put It Together

Complete reference implementation

The complete class combines persistent fields, constructor validation, accessors, protective mutators, returned results, and a local variable. Use it as a reference after attempting the earlier questions.

public class CampusCard
{
    private String owner;
    private int balance;
    private int totalSpent;

    public CampusCard(String owner, int openingBalance)
    {
        this.owner = owner;
        if(openingBalance >= 0) {
            balance = openingBalance;
        }
        else {
            balance = 0;
        }
        totalSpent = 0;
    }

    public String getOwner()
    {
        return owner;
    }

    public int getBalance()
    {
        return balance;
    }

    public int getTotalSpent()
    {
        return totalSpent;
    }

    public boolean topUp(int amount)
    {
        if(amount > 0) {
            balance = balance + amount;
            return true;
        }
        else {
            return false;
        }
    }

    public boolean pay(int amount)
    {
        if(amount > 0 && amount <= balance) {
            balance = balance - amount;
            totalSpent = totalSpent + amount;
            return true;
        }
        else {
            return false;
        }
    }

    public int refundBalance()
    {
        int amountToRefund = balance;
        balance = 0;
        return amountToRefund;
    }
}
