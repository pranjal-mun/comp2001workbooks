Lecture summary

A stream pipeline can choose tracks, read their titles or lengths, then print or combine the values. This Playlist uses the Track class from the lecture. With the five-track example, John Coltrane gives two titles, Blue Train and Naima, a count of 2, and a total of 908 seconds. All five tracks stay in the list.

import java.util.ArrayList;

public class Playlist
{
    private ArrayList<Track> tracks;

    public Playlist()
    {
        tracks = new ArrayList<>();
    }

    public void addTrack(Track track)
    {
        tracks.add(track);
    }

    public void printTitlesByArtist(String artist)
    {
        tracks.stream()                              // source: Track objects
              .filter(t -> t.getArtist().equals(artist)) // predicate: true lets a track through
              .map(t -> t.getTitle())                 // now String titles
              .forEach(title -> System.out.println(title)); // terminal action
    }

    public long countTracksByArtist(String artist)
    {
        return tracks.stream()                       // fresh stream for another result
                     .filter(t -> t.getArtist().equals(artist))
                     .count();                       // terminal: returns long
    }

    public int totalDurationByArtist(String artist)
    {
        return tracks.stream()
                     .filter(t -> t.getArtist().equals(artist))
                     .map(t -> t.getDurationSeconds()) // now the seconds
                     .reduce(0, (total, seconds) -> total + seconds);
                                                     // identity 0; accumulator adds seconds
    }
}
termmeaning
stream and sourcetracks.stream() opens a view of the list's elements for processing, not a stored copy or a list with indexed access. The pipelines above leave the list's membership, order and track fields unchanged.
pipeline stagesa source, zero or more intermediate operations, then one terminal operation. Intermediate operations return streams; the terminal operation starts processing and returns a result or performs an action.
filter and predicatefilter takes a boolean test for one element. true passes it onward; false leaves it out. The element type stays Track; the source list loses nothing.
map and element typemap supplies one value for each input that reaches it. Titles give String elements; the durations become numbers in this stream. After mapping to titles, you cannot call Track methods on them.
forEacha terminal operation that runs an action for each arriving element and returns no value. Here it prints each title; it does not return another stream.
counta terminal operation returning a long, not an int. It counts the elements that reach it, so the Coltrane filter gives 2.
reduce, identity and accumulatorreduce(0, (total, seconds) -> total + seconds) combines seconds into one total. The identity 0 leaves addition unchanged. The accumulator takes the total so far and the next value, then returns the new total. Coltrane gives 0, 643, 908.
empty streamwith no matching tracks, forEach runs no action, count returns 0, and identity-based reduce returns its identity without calling the accumulator. An empty playlist gives the same results.
one stream per resulta stream cannot be reused after a terminal operation. Call tracks.stream() again for another result. You cannot put filter after count, because a long has no stream operations.
loop or pipelinea short pipeline suits choosing, transforming and combining values. A loop can read better when you need an index, an early exit or several updates. Both are valid; choose the version whose steps are easier to follow.

1. Playlist

The running example

This lecture keeps the Track and Playlist classes from Lectures 6 to 8. A Track keeps a title, an artist and a duration in seconds:

public class Track
{
    private String title;
    private String artist;
    private int durationSeconds;

    public Track(String title, String artist, int durationSeconds)
    {
        this.title = title;
        this.artist = artist;
        this.durationSeconds = durationSeconds;
    }

    public String getTitle()
    {
        return title;
    }

    public String getArtist()
    {
        return artist;
    }

    public int getDurationSeconds()
    {
        return durationSeconds;
    }

    public void printDetails()
    {
        System.out.println(artist + " - " + title + " (" + durationSeconds + " s)");
    }
}

Three open questions

Lecture 8 ended with three jobs that we could not yet do with one collection method:

  • print only the Coltrane tracks;
  • get the title of each track instead of the track itself;
  • get the total playing time as one number.

forEach runs an action on every element and gives nothing back, so it cannot hand us a total. removeIf can select tracks, but it selects them by deleting the others from the list, which is not what “print only the Coltrane tracks” asks for. A stream pipeline can do any of these steps, one stage at a time.

2. Streams

Opening a stream

Every collection, including ArrayList, has a method stream(). It returns a stream: a sequence of the list's elements, in list order, ready to be processed by a chain of operations. These two fragments print the same five lines:

for(Track track : tracks) {
    track.printDetails();
}
tracks.stream()
      .forEach(track ->
          track.printDetails());

Here the stream does nothing that tracks.forEach(...) could not do alone. Streams pay off when we put other operations between stream() and the final action, as the next sections do. Each operation is written on its own line, starting with a dot, so the pipeline reads from top to bottom.

Pipeline stages

A pipeline has three kinds of stage:

StageExamplesHow many
sourcetracks.stream()one
intermediatefilter, mapzero or more
terminalforEach, count, reduceexactly one

The source supplies the elements. Each intermediate operation receives a stream and returns a new stream, so another operation can follow it. The terminal operation ends the pipeline: it performs an action or returns a result that is not a stream. Nothing happens until the terminal operation is called. A pipeline with no terminal operation describes some work but never does it.

Streams and lists

A stream is not a second list. It does not store its elements; it passes them through the operations, one at a time.

ArrayListStream
Stores its elementsPasses elements from a source through operations
Has indexed access: get(0)Has no index and no get
Supports add and removeOperations return new streams; the source is not changed
Has a finite sizeCould in principle be endless
Can be visited many timesIs used up by its terminal operation

Because the operations return new streams, a pipeline never adds to, removes from or reorders the list it came from. Our pipelines also never call a method that changes a track. After any pipeline in this lecture, the playlist still holds the same five tracks in the same order.

3. Filtering

The filter method

filter is an intermediate operation. Its argument is a predicate: a lambda that takes one element and returns a boolean, as for removeIf in Lecture 8. For each element, a result of true lets that element continue to the next stage, and false leaves it out. Here are two versions of a method that prints the tracks by one artist:

public void printByArtistLoop(String artist)
{
    for(Track t : tracks) {
        if(t.getArtist().equals(artist)) {
            t.printDetails();
        }
    }
}
public void printByArtistStream(String artist)
{
    tracks.stream()
          .filter(t -> t.getArtist().equals(artist))
          .forEach(t -> t.printDetails());
}

The if test of the loop becomes the predicate, and the body of the if becomes the action of forEach. For "John Coltrane", the predicate is true for Blue Train and Naima, so these two tracks reach forEach, in their original order. The other three are not printed, but they stay in the list.

The elements that pass are the same Track objects, not copies, so the element type after filter is still Track. A filter can pass all of its elements, some of them or none. It never passes more than it receives.

Filtering and removal

filter and removeIf both take a predicate, but true means opposite things:

MethodMeaning of trueEffect on the list
filter (on a stream)let this element continuenone
removeIf (on the list)delete this elementthe list gets shorter

Use filter when you want to work with some elements and keep them all. Use removeIf only when the elements should really leave the collection.

Chained filters

Two filters can follow each other. Each one receives only the elements that passed the one before. This pipeline prints the tracks that are longer than 250 seconds and shorter than 400 seconds:

tracks.stream()
      .filter(t -> t.getDurationSeconds() > 250)
      .filter(t -> t.getDurationSeconds() < 400)
      .forEach(t -> t.printDetails());

The same selection can be written as one filter with &&: filter(t -> t.getDurationSeconds() > 250 && t.getDurationSeconds() < 400). Two short predicates are often easier to read than one long one.

4. Mapping

The map method

map is an intermediate operation whose lambda takes one element and returns a value. That value, not the element, continues to the next stage. Here are two versions of printAllTitles:

public void printTitlesLoop()
{
    for(Track t : tracks) {
        String title = t.getTitle();
        System.out.println(title);
    }
}
public void printTitlesStream()
{
    tracks.stream()
          .map(t -> t.getTitle())
          .forEach(title -> System.out.println(title));
}

The line String title = t.getTitle(); in the loop becomes the lambda of map. Five tracks go into map and five titles come out. map always produces exactly one value for each element it receives; it never drops one. It does not change the tracks either: reading a title leaves the track as it was.

The type after map

map can change the type of the elements. Before map(t -> t.getTitle()) the stream holds Track objects; after it, the stream holds String values, because getTitle() returns a String. In the same way, map(t -> t.getDurationSeconds()) turns the five tracks into the five numbers 224, 643, 330, 265 and 379.

Every later lambda in the pipeline receives the new type. Its parameter is declared by the lambda itself, and Java gives it the element type of the stream at that point, whatever name we choose for it.

Filter, then map

Filtering and mapping often appear together. The filter must come first when its predicate needs the whole track:

public void printTitlesByArtist(String artist)
{
    tracks.stream()
          .filter(t -> t.getArtist().equals(artist))
          .map(t -> t.getTitle())
          .forEach(System.out::println);
}

System.out::println is the method reference from Lecture 8: each title is passed to println.

Counting

count() is a terminal operation that returns how many elements reach it, as a long. A long is a whole number like an int, with a much larger range. To count the tracks by one artist, filter and then count:

public long countByArtist(String artist)
{
    return tracks.stream()
                 .filter(t -> t.getArtist().equals(artist))
                 .count();
}

If nothing passes the filter, count() returns 0.

6. Reduction

Kinds of operation

forEach and count end a pipeline in two different ways: one performs an action and returns nothing, the other returns a number. The third terminal operation of this lecture, reduce, combines all the values that reach it into one value. No terminal operation returns a stream (forEach returns nothing at all), so no stream operation can follow it.

The accumulator

Here are two versions of a method that returns the total playing time:

public int totalLoop()
{
    int total = 0;
    for(Track t : tracks) {
        total = total + t.getDurationSeconds();
    }
    return total;
}
public int totalStream()
{
    return tracks.stream()
                 .map(t -> t.getDurationSeconds())
                 .reduce(0, (total, seconds) -> total + seconds);
}

reduce takes two arguments. The first, 0, is the identity: the starting value, like int total = 0; in the loop. The second is the accumulator, a lambda with two parameters. The first parameter, total, holds the result so far; the second, seconds, holds the next value from the stream. The lambda returns the new result, which becomes total on the next call. This is the line total = total + t.getDurationSeconds(); of the loop, written as a lambda.

For the first track, the accumulator receives 0 and 224 and returns 224. For the second it receives 224 and 643 and returns 867, and so on. The last returned value is the result of reduce.

Choosing an identity

The identity must leave a value unchanged when it is combined with it. For addition, the identity is 0, because 0 + x is x. For multiplication it would be 1, because 1 * x is x. A wrong identity, such as 10 for a sum, is added into the result and makes every total 10 too large.

reduce is not limited to numbers. Any two values of the same type can be combined, as long as the accumulator returns that type too. Question 6.4 asks you to join text with it.

Empty results

If no element reaches the terminal operation, because the source list is empty or a filter passes nothing, the pipeline still finishes normally. forEach runs its action zero times and count() returns 0. reduce has nothing to combine, so it never calls the accumulator and returns the identity. This is one more reason to choose the identity carefully: it is the answer for an empty stream.

7. Reading pipelines

Values at each stage

To read a pipeline, go down it one stage at a time and ask two questions: how many values continue, and what type are they? For example:

tracks.stream()
      .filter(t -> t.getArtist().startsWith("M"))
      .map(t -> t.getDurationSeconds())
      .forEach(seconds -> System.out.println(seconds));

The source supplies 5 tracks. The String method startsWith returns true if the text begins with the given text, so the filter passes the 2 tracks by Massive Attack (Teardrop and Angel), still as Track objects. The map turns those 2 tracks into 2 numbers, 330 and 379, and forEach prints them.

Lambda shapes

Each operation expects a lambda of a particular shape:

OperationLambda receivesLambda returns
filterone elementtrue or false
mapone elementone value for the next stage
forEachone elementnothing; it performs an action
reducethe result so far and the next valuethe new result

The compiler checks the types, but not the purpose. A boolean lambda passed to map compiles: it produces a stream of boolean values instead of selecting elements.

Finishing a pipeline

After stream(), only an intermediate operation returns a stream, so only an intermediate operation can be followed by another stream operation. A terminal operation must come last. count() returns a long, and a long has no methods at all, so writing .filter(...) after .count() is a compile error. A pipeline without a terminal operation compiles, but none of its lambdas ever run.

Stream reuse

A stream can be used only once. After its terminal operation has run, the stream is used up, and calling another operation on it throws an exception when the program runs. To compute two results from the same list, start two pipelines, each with its own call to tracks.stream(). That is why countTracksByArtist and totalDurationByArtist each begin with tracks.stream(). The list itself can supply as many streams as we need.

8. Choosing a style

Loops and pipelines

A pipeline is not always better than a loop. A short pipeline fits a job that selects elements, changes them and then prints, counts or combines them, with one clear purpose per stage. A loop is clearer when the job needs an index, must stop at the first match, or updates several variables at once. For example, this search keeps an index and returns as soon as it finds a match:

public int findFirstTrackIndex(String title)
{
    int index = 0;
    while(index < tracks.size()) {
        if(tracks.get(index).getTitle().equals(title)) {
            return index;
        }
        index = index + 1;
    }
    return -1;
}

The pipelines in this lecture have no index, and they always visit every element. Shorter code is not automatically clearer: choose the version that a reader can check most easily.
