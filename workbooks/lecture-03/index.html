1. Class Skeleton

Class definitions

Lecture 2 used finished classes as a client. We created objects, called methods, and traced state. We now look inside a class definition and write the parts that create that state.

A class definition has an outer wrapper and an inner body:

public class SmartLamp
{
    // fields, constructors, and methods belong here
}

public and class are Java keywords. The programmer chooses the name SmartLamp. By convention, class names begin with an uppercase letter, and the source file is named SmartLamp.java. The outer braces enclose the class body.

The class body normally contains three kinds of members:

memberjob
fieldstores part of each object's state
constructorestablishes a new object's initial state
methodprovides behavior; implementation details continue in Lecture 4

Comments such as // fields go here explain code to people. They do not change how the program runs.

2. Fields

Field declarations

A field is a variable that belongs to an object. Fields are also called instance variables: every instance has its own set of field values. A field keeps its value for as long as its object exists, unless a later assignment changes that value.

The SmartLamp class needs four fields:

private String location;
private boolean on;
private int brightness;
private String color;

Read a field declaration from left to right:

codeaccesstypenameend
private int brightness;privateintbrightnesssemicolon

The type limits the values that may be stored. String is used for text, boolean for true or false, and int for whole numbers. private keeps ordinary client code from assigning fields directly; code inside the class can still use its own fields.

Field declarations define the state structure, but not the intended starting values. Java supplies default field values, but a constructor should make the class's initialization decisions explicit.

Fields of separate objects

Equal values do not mean shared storage. Each use of new constructs a fresh object with its own fields.

3. Constructors

The constructor

A constructor runs when new creates an object. Its main job is to assign intentional initial values to the new object's fields.

public SmartLamp(String lampLocation)
{
    location = lampLocation;
    on = false;
    brightness = 0;
    color = "warm white";
}

A constructor has the same name as its class. It has no return type, not even void. The parameter list is inside parentheses, and the constructor body is the block inside braces.

The caller supplies the location. The class chooses the other three starting values. After construction, the lamp is ready to answer the operations established in Lecture 2.

Tracing a constructor

For new SmartLamp("Window"), the parameter lampLocation first receives "Window". Then the four assignments run in order:

stepstatementfield value afterward
1location = lampLocation;location is "Window"
2on = false;on is false
3brightness = 0;brightness is 0
4color = "warm white";color is "warm white"

Run the construction and let the supplied printState method show the result. The line marked added is not part of the lecture listing; it only lets you see the fields.

Explicit assignments are useful even when a Java default happens to be the same value. They document intent and show that no field was forgotten.

4. Passing Values

Parameters and arguments

A parameter is a typed variable declared in a constructor or method header. An argument is the actual value supplied by one call.

public SmartLamp(String lampLocation)  // parameter

new SmartLamp("Desk")                 // argument

During this call, lampLocation receives "Desk". The parameter is temporary: it exists only while the constructor executes. If the object needs the value later, the constructor must store it in a field.

A constructor may receive several values:

public Book(String title, String author, int pages)

Book novel = new Book(
    "Kindred", "Octavia E. Butler", 288
);

Arguments match parameters by position and compatible type. Parameter names help readers understand the definition; those names do not appear in the call.

5. Assignment and this

Assignment

An assignment has a variable on the left and an expression on the right:

location = lampLocation;

Read it from right to left: read the value in lampLocation, then store that value in location. Assignment is directional; it is not a mathematical equality. A later assignment replaces the variable's previous value.

The value on the right must be compatible with the type of the variable on the left. For example, an int may be assigned to brightness, but a text value may not.

The this keyword

It is common to use the same meaningful name for a field and a parameter:

private String location;

public SmartLamp(String location)
{
    location = location;   // compiles, but does not set the field
}

Inside the constructor, the parameter is the closer declaration. The unqualified name location therefore means the parameter. The wrong statement assigns the parameter to itself and leaves the field at its default value.

The keyword this refers to the current object:

public SmartLamp(String location)
{
    this.location = location;
}

Read this statement as: “Store the parameter named location in the current object's field named location.” The left side is a field; the right side is a parameter.

6. The Complete Class

The complete SmartLamp class

The complete class below combines the class header, fields, constructor, parameters, assignment, and this. The getters and printState are included so the program can print the fields and check what the constructor did. Writing those methods is part of Lecture 4. This is the SmartLamp that the example boxes on this page compile against.

public class SmartLamp
{
    private String location;
    private boolean on;
    private int brightness;
    private String color;

    public SmartLamp(String location)
    {
        this.location = location;
        on = false;
        brightness = 0;
        color = "warm white";
    }

    public String getLocation()
    {
        return location;
    }

    public boolean isOn()
    {
        return on;
    }

    public int getBrightness()
    {
        return brightness;
    }

    public String getColor()
    {
        return color;
    }

    public void printState()
    {
        System.out.println(location + ": on=" + on
                           + ", brightness=" + brightness
                           + ", color=" + color);
    }
}

Two objects from one class

Each call to new creates a fresh object. The location arguments are different, while the other initial field values are intentionally the same. Equal values do not imply shared fields.
