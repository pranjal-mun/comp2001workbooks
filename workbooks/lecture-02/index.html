The whole lecture in 10 minutes

Short on time? This section says everything the lecture says, without the practice. Read it once, then come back to the numbered sections for the exercises. Big idea: a Java program models part of the world as objects. Each object remembers things (its state) and can be asked to do things (its behavior). This lecture uses a finished SmartLamp class; you learn to use objects, not yet to write classes.

1. Class or object

A class (SmartLamp) describes a kind of object: what every lamp can remember and do. An object, or instance, is one specific lamp made from that class. Class names start uppercase (SmartLamp), variable names lowercase (deskLamp). Two lamps have the same kinds of fields, but each keeps its own values: changing one does not change the other.

2. Create objects
SmartLamp deskLamp = new SmartLamp("Desk");

SmartLamp is the type, deskLamp the reference variable, new builds a fresh object, and SmartLamp("Desk") calls the constructor with one argument. The variable holds a reference to the object, not the object itself. The constructor sets the initial state: on = false, brightness = 0, color = "warm white". Every new makes a separate object, even with the same argument. SmartLamp windowLamp; alone declares a variable and creates nothing.

3. Call methods

deskLamp.turnOn(); reads as "ask the object deskLamp refers to to run turnOn". The receiver before the dot decides which object changes; readingLamp.turnOn(); changes a different lamp. You can use a method from its header alone:

headereffect
void turnOn(), void turnOff()change state
void setBrightness(int newBrightness), void setColor(String newColor)store a supplied value
int getBrightness()report state
void printState()display state
4. Pass values

In deskLamp.setBrightness(70); the parameter is newBrightness (named in the header) and the argument is 70 (supplied by this call). Types must match: 70 fits int, "70" does not; text needs quotes (setColor("daylight"), not setColor(daylight)); turnOn(1) fails because turnOn takes no arguments. The method name plus the parameter types form the signature, setBrightness(int). The return type and the parameter names are not part of it.

5. Track state

Each call starts from the state the previous call left. Trace one receiver at a time:

afteronbrightnesscolor
constructionfalse0warm white
turnOn()true0warm white

setColor("daylight")true70daylight

The reading lamp is untouched by all of this. A query such as int level = deskLamp.getBrightness(); returns a value without changing state; a void method returns nothing but may change state. Returning a value and printing it are different things. State can be observed with queries, printed output, a debugger, BlueJ's object inspector, or a hand-written trace; the inspector only reveals state, it does not create it.

6. Put it together: the client pattern
SmartLamp deskLamp = new SmartLamp("Desk");

The two printState() calls print the lines below, and level holds 70.

1. Class or Object

A class describes a kind of object

An object-oriented program models selected parts of a problem domain. A class describes a kind of object. It defines the kinds of state and behavior that every object of that class can have. An object, also called an instance, is one specific entity created from that class.

This workbook uses a class named SmartLamp. It can describe many lamp objects: a desk lamp, a reading lamp, or a window lamp. The class is the general description; each lamp object has its own current values.

classpossible objectanother object
SmartLampdesk lampreading lamp
Studentone student named Aminaone student named Bao
Bookthis copy of a novelanother copy of the same novel

Class names normally begin with an uppercase letter. Variable names normally begin with a lowercase letter. This convention helps readers distinguish SmartLamp from a variable such as deskLamp.

Objects have state and behavior

An object's state is the current set of values stored in its fields. The smart-lamp state includes its location, whether it is on, its brightness, and its color. Its behavior is the set of operations that clients can request through methods.

state examplesbehavior examples
location is "Desk"; on is true; brightness is 70turn on; change brightness; report current state

Objects of the same class have the same kinds of fields and methods, but each object stores its own field values. Changing the desk lamp does not automatically change the reading lamp.

3. Call Methods

The receiver comes before the dot

Objects provide methods through a public interface. A method call sends a request to one selected object:

deskLamp.turnOn();

Read this as, “Ask the object referred to by deskLamp to run turnOn.” The receiver is deskLamp, the method is turnOn, and the empty parentheses mean that no arguments are supplied.

The first call changes the desk-lamp object. The second call changes the reading-lamp object. The receiver before the dot determines which object receives the request.

Read a small public interface

You can use a method without seeing its internal statements. The header tells you the return type, method name, and parameters.

method headerclient meaning
void turnOn()Turn this lamp on.
void turnOff()Turn this lamp off.
void setBrightness(int newBrightness)Store a supplied brightness.
void setColor(String newColor)Store a supplied color.

Some methods change state. Some return information. Some display information. Not every method has the same effect.

4. Pass Values

Parameters allow varied requests

Turning a lamp on needs no extra information. Setting a brightness needs the desired value:

deskLamp.setBrightness(70);

Compare the call with the method header:

void setBrightness(int newBrightness)

The parameter newBrightness is the named input in the method header. The argument 70 is the value supplied by this particular call.

The argument must be compatible with the parameter type. Java accepts 70 for an int parameter but not "70". A String value uses double quotes:

deskLamp.setColor("daylight");

Without quotes, Java treats daylight as a name rather than as text. Parameter names help human readers, but calls supply values, not the parameter names.

The method name and parameter types form the method's signature. The signature of the color method is setColor(String). The return type is not part of the Java signature.

5. Track State

Trace changes in execution order

An object's state is the current set of field values. Each method call starts from the state left by the preceding call. Trace one receiver at a time.

after callonbrightnesscolor
constructionfalse0warm white
turnOn()true0warm white
setBrightness(70)true70warm white
setColor("daylight")true70daylight

Because all three calls target deskLamp, the reading lamp remains off at brightness 0 with color "warm white".

Queries return information about state

The return type int states that the call produces an integer result. The returned value is stored in level. A query method can report state without changing it.

A void method returns no result value, but it may still do important work. For example, turnOn() returns no value and changes the on/off field.

headerreturn valuemain effect
void turnOn()nonechange state
int getBrightness()one intreport state
void printState()nonedisplay state

Inspection is another view of the same state

State can be observed with query methods, purposeful output, a debugger, an object inspector, or a hand-written trace table. In BlueJ labs, the object inspector shows the fields and current values of one selected object. Call a mutating method and connect each visible field change to that call.

The inspector does not create the state. It reveals state already stored in the running object. Inspecting one lamp does not show the state of every lamp.

Complete provided class

The following finished class is provided so that you can compile and run the client program. You are not yet expected to reproduce its implementation from memory. Lectures 3 and 4 explain these fields, constructor assignments, mutators, accessors, and return statements. This is the SmartLamp that every code box on this page compiles against.

public class SmartLamp
{
    private String location;
    private boolean on;
    private int brightness;
    private String color;

    public SmartLamp(String location)
    {
        this.location = location;
        on = false;
        brightness = 0;
        color = "warm white";
    }

    public void turnOn()
    {
        on = true;
    }

    public void turnOff()
    {
        on = false;
    }

    public void setBrightness(int newBrightness)
    {
        brightness = newBrightness;
    }

    public void setColor(String newColor)
    {
        color = newColor;
    }

    public String getLocation()
    {
        return location;
    }

    public boolean isOn()
    {
        return on;
    }

    public int getBrightness()
    {
        return brightness;
    }

    public String getColor()
    {
        return color;
    }

    public void printState()
    {
        System.out.println(location + ": on=" + on
                           + ", brightness=" + brightness
                           + ", color=" + color);
    }
}

public class GameCharacter
{
    private String name;
    private int health;
    private int xPosition;

    public GameCharacter(String name, int health)
    {
        this.name = name;
        this.health = health;
        xPosition = 0;

    public void move(int distance)
    {
        xPosition = xPosition + distance;
    }

    public void takeDamage(int amount)
    {
        health = health - amount;
    }

    public String getName()
    {
        return name;
    }

    public int getHealth()
    {
        return health;
    }

    public int getXPosition()
    {
        return xPosition;
    }

    public void printState()
    {
        System.out.println(name + ": health=" + health
                           + ", xPosition=" + xPosition);
    }
}
