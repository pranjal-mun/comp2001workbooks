public class Flashlight
{
    private Battery battery;            // field whose type is a class: holds a reference
    private boolean on;
    public Flashlight()
    {
        battery = new Battery(100);     // creates the collaborator: one new Battery object
        on = false;
    }
    public Flashlight(Battery battery)
    {
        this.battery = battery;         // receives an existing object: no new Battery
        on = false;
    }
    public void useForOneMinute()
    {
        if(on) {
            battery.drain(1);           // external call: the receiver is battery
            updatePowerState();         // internal call: the receiver is this object
        }
    }
    public int getBatteryCharge()
    {
        return battery.getCharge();     // delegation: no duplicate charge field
    }
}

1. Responsibilities

A working class can still have too many responsibilities

Imagine a first attempt at a flashlight class with these fields:

private boolean on;
private int batteryCapacity;
private int batteryCharge;

One Flashlight class could manage all three fields, and the program would work. But this mixes light behaviour with battery rules. If a camera, a radio, or a toy also needs a rechargeable battery, the capacity/charge/drain/recharge code would have to be repeated in each of those classes.

  • A responsibility is a piece of state or behaviour that a class is expected to own.
  • Modularization means dividing a program into well-defined parts.
  • Abstraction means using a part through what it does, without repeatedly reasoning about its internal details.

2. Class-Typed Fields

A class name is a type

public class Flashlight
{
    private Battery battery;
    private boolean on;
}

Battery is the type; battery is the field name. A class name can be used as a type anywhere an object type is allowed:

private Engine engine;                    // field
Battery spare;                            // local variable
public void install(Battery replacement)  // parameter

The declared type controls which methods may be called through that variable.

Reference field and object are separate

A primitive variable stores a value directly: int count = 3; stores 3. An object-typed variable stores a reference, not the object's fields: Battery battery; stores a reference to a Battery object, or no reference at all.

At the beginning of a constructor body, before any assignment statements run, an object field has the default value null, meaning "no object reference." This is not a fully constructed object whose constructor simply has not run yet. It is the absence of any object reference.

3. Creating and Receiving Collaborators

Declaration, construction, and assignment

battery = new Battery(100);

This one line combines two distinct ideas, on top of a declaration that already happened earlier:

  • declaration (earlier): private Battery battery; introduced the name and type;
  • construction: new Battery(100) creates one object and runs its constructor;
  • assignment: = stores the resulting reference in the field.

The default constructor creates its own collaborator

public Flashlight()
{
    battery = new Battery(100);
    on = false;
}

Three states follow in order: the constructor body begins and battery is null; new Battery(100) runs and produces one Battery object; the reference is assigned to battery.

Overloaded constructors

Placing both constructors side by side: a class may have more than one constructor when their parameter lists are distinct. Java selects the matching constructor by comparing the argument list at the call site against each constructor's parameter list.

Internal calls use the current object

public void useForOneMinute()
{
    if(on) {
        battery.drain(1);
        updatePowerState();
    }
}

private void updatePowerState()
{
    if(battery.isEmpty()) {
        on = false;
    }
}

updatePowerState() has an implicit receiver: this, the current object. Calling it is not recursion; it is one ordinary method asking another method of the same object to run.

Primitive copy versus reference copy

int a = 3;

a = 2;
Battery first = new Battery(3);
Battery second = first;
first.drain(1);

Primitive assignment copies a value into a separate box. Reference assignment copies an arrow: second and first then refer to the same Battery object. Two variables or fields that refer to the same object are called aliases.

6. Delegation

One source of truth and delegation

Fact or operationOwner and reason
battery capacity and chargeBattery: it enforces battery rules
drain and rechargeBattery: they change battery state
whether the light is onFlashlight: it is light state
whether usage is allowedFlashlight, informed by Battery: it coordinates the device
reporting chargeFlashlight delegates to Battery: avoids duplicate state

Delegation is an ordinary method call used to give a subtask to the object responsible for it.
