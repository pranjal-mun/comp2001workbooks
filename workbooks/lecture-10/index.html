Lecture summary

This lecture uses three library classes inside one class of our own. HelpBot cleans a question with String methods, picks one of four general replies with a Random object, and keeps ratings in an ArrayList<Integer>. For the ratings 5, 3 and 4 it reports 3 ratings and an average of 4; the ratings 0 and 6 are ignored. Here is the finished class, with its comments. Its replies still ignore what the question says; Lecture 11 fixes that with a map.

import java.util.ArrayList;
import java.util.Random;

/**
 * Answers course questions with a general reply and keeps
 * the ratings that users give.
 * @author Pranjal Patra
 * @version 1.0
 */
public class HelpBot
{
    private ArrayList<String> generalReplies;
    private ArrayList<Integer> ratings;
    private Random randomGenerator;

    /**
     * Create a help bot with its general replies and no ratings.
     */
    public HelpBot()
    {
        generalReplies = new ArrayList<>();
        ratings = new ArrayList<>();
        randomGenerator = new Random();
        fillGeneralReplies();
    }

    /**
     * Answer one question.
     * @param question The text typed by the user; must not be null.
     * @return A general reply, or a prompt when nothing was typed.
     */
    public String replyTo(String question)
    {
        String cleaned = clean(question);
        if(cleaned.isEmpty()) {
            return "Please type a question.";
        }
        return pickGeneralReply();
    }

    /**
     * Remove the spaces around a question and put it in lower case.
     * @param question The typed text; must not be null.
     * @return The cleaned text. The original string is unchanged.
     */
    public String clean(String question)
    {
        return question.trim().toLowerCase();
    }

    /**
     * Choose one general reply at random. The call nextInt(bound)
     * returns a value from 0 up to bound - 1, which is exactly the set
     * of valid indices for a list of that size.
     * @return One of the general replies.
     */
    public String pickGeneralReply()
    {
        int index = randomGenerator.nextInt(generalReplies.size());
        return generalReplies.get(index);
    }

    // Question 7.1 asks you to write the Javadoc comment for this method.
    public void addRating(int rating)
    {
        if(rating >= 1 && rating <= 5) {
            ratings.add(rating);
        }
    }

    /**
     * Return the number of ratings recorded so far.
     * @return The number of ratings.
     */
    public int numberOfRatings()
    {
        return ratings.size();
    }

    /**
     * Work out the average of the recorded ratings. Each Integer in the
     * list is unboxed into the int loop variable.
     * @return The whole-number average, or 0 when no rating exists.
     */
    public int averageRating()
    {
        if(ratings.isEmpty()) {
            return 0;
        }
        int total = 0;
        for(int rating : ratings) {
            total = total + rating;
        }
        return total / ratings.size();
    }

    /**
     * Build the list of general replies. This method is private because
     * it is a step in building a HelpBot, not an operation that other
     * classes should call.
     */
    private void fillGeneralReplies()
    {
        generalReplies.add("Can you describe that in more detail?");
        generalReplies.add("Have you checked the course web page?");
        generalReplies.add("That question comes up often. Let us look at it together.");
        generalReplies.add("Please post that on the discussion board so others can see the answer.");
    }
}

1. Library

The help desk bot

The example for Chapter 6 is a class called HelpBot. It answers questions at a course help desk. A question arrives as a String parameter, and the reply goes back as a String. There is no keyboard input and no window; a demo class calls the methods and prints what they return. The first version gives every question the same reply:

public String replyTo(String question)
{
    return "Can you describe that in more detail?";
}

During this lecture the bot gets three improvements. It cleans up the question text, it chooses one of four general replies at random, and it keeps the ratings that users give its replies. All three use classes that we do not write ourselves. The examples in this workbook always use the same data:

  • the messy question " How do I SUBMIT my work? ", with three spaces in front and two at the end;
  • the four general replies listed in Section 5;
  • the ratings 5, 3 and 4, in that order.

Questions passed to the bot are never null.

Library classes

Java comes with a large class library: thousands of classes that someone else has written and tested. We have used several already. String holds text, ArrayList holds a list of objects, and System gives us System.out.println. None of us has read the source code of ArrayList. We could still use it, because we knew the names of its methods, what each one takes, what it returns, and what it does.

That is the normal way to work. A good programmer knows a few important library classes by name and knows how to look up the rest. Using an existing class is usually better than writing our own version: it is already finished, and it has been tested by many other programs.

Packages and qualified names

The classes of the library are grouped into packages. A package is a named group of related classes. For example, java.util holds ArrayList and Random, and java.lang holds String, Integer, System and Math. Packages can contain other packages: java.util.function is a separate package inside java.util.

The qualified name of a class is its package name, a dot, and the class name. The qualified name of Random is java.util.Random. Two classes in different packages may have the same short name, and the qualified name tells them apart.

Imports

An import statement goes at the top of the file, before the class. It lets the file use the short name of a class from another package:

import java.util.ArrayList;
import java.util.Random;

Without the import we can still use the class, but every use must then be the qualified name, as in new java.util.Random(). The form import java.util.*; imports every class of java.util. It does not import the classes of the packages inside it, such as java.util.function. In this course we import one class per line, because the list at the top then shows exactly which classes the file uses.

The classes of java.lang are imported automatically. That is why String, Integer and System never needed an import. An import only makes a name available. It does not copy any code into our file, and it does not make the program larger or slower.

2. Interfaces

Reading documentation

Every class in the library has documentation, and it is the first place to look when we want to use the class. The documentation of java.lang.String gives:

  • the package and a description of what the class is for;
  • a summary of its constructors and methods;
  • for each method, its parameters and its return type;
  • a full description of each method, including any limits on the arguments and what happens when they are broken.

The method name is often not enough. For example, substring(int beginIndex, int endIndex) returns part of a string, but the name does not say whether the character at endIndex is included. The description does: it is not.

To open the documentation in BlueJ, choose Help, then Java Class Libraries. It opens in a web browser, where each class has its own page.

Method headers

Each method in the documentation starts with its header:

public boolean startsWith(String prefix)

From left to right, a header has the access modifier (public: other classes may call it), the return type (boolean: it returns true or false), the method name, and the parameter list in parentheses. Here the list has one parameter, of type String.

The method name and the parameter types together are the method's signature: startsWith(String). The return type is not part of the signature, and neither is the parameter name. The name prefix only tells the reader what the value is for. When we call the method we can pass any String expression, whatever our own variable is called.

Interface and implementation

The public part of a class is its interface: the constructors and methods that other classes may use, with their headers and descriptions. The code that makes those methods work is the implementation: the fields, the private helper methods and the method bodies. The documentation shows the interface and hides the implementation.

A caller only needs the interface. To get the first element of a list we call get(0), and we never need to see how get finds it. This also protects us. The authors of ArrayList can change its implementation, and our code keeps working, as long as the interface stays the same.

Java also has a keyword interface. That is a different idea, which we meet in a later chapter. In this chapter, “interface” means the public part of a class.

Generic classes

The documentation of ArrayList calls the class ArrayList<E>. The E is a placeholder for the element type that we supply when we use the class. It appears again in the method headers:

In the documentationFor an ArrayList<String>
boolean add(E e)boolean add(String e)
E get(int index)String get(int index)
E remove(int index)String remove(int index)

A class that takes a type in angle brackets is called a generic or parameterized class. E is not a real class, and we never import it. When we write new ArrayList<>(), the empty angle brackets tell Java to use the element type from the declaration on the left.

3. Strings

Cleaning text

People type questions with extra spaces and with capital letters in odd places. Before the bot looks at a question, it cleans the text with two String methods. trim() removes the spaces at the start and the end; the spaces between words stay. toLowerCase() changes every capital letter to a small one.

StepTextLength
typed" How do I SUBMIT my work? "29
after trim()"How do I SUBMIT my work?"24
after toLowerCase()"how do i submit my work?"24

length() counts every character, including the spaces. The trimmed text has 24 characters, and 4 of them are the spaces between the words. The typed question adds 3 spaces in front and 2 at the end, so its length is 29.

Searching inside a string

These methods answer questions about a string. None of them changes it.

MethodWhat it returns
length()the number of characters, as an int
isEmpty()true when the length is 0
contains(s)true when s appears anywhere in the string
startsWith(s), endsWith(s)true when the string begins, or ends, with s
indexOf(s)the position where s first starts, or -1 if it is not there
substring(a, b)a new string made of the characters from position a up to, but not including, position b
equals(s)true when the two strings have the same characters

All of these are case sensitive. On the typed question, contains("submit") is false, because the question says SUBMIT. On the cleaned question it is true, and indexOf("submit") is 9. Remember from Lecture 7 that strings are compared with equals, never with ==.

Positions and substrings

The characters of a string are numbered from 0, like the elements of a list. In "how do i submit my work?", the h is at position 0 and the space after how is at position 3. substring(0, 3) includes position 0 and stops just before position 3, so it returns "how", which has three characters. In general, substring(a, b) has b - a characters. A position below 0 or past the end of the string stops the program with an error.

Immutable strings

A String object is immutable: once it is created, its characters never change. A method such as trim() does not edit the string it is called on. It builds a new string and returns it.

String word = "  late  ";
word.trim();                        // the new string is thrown away
System.out.println(word.length());  // 8

word = word.trim();                 // word now refers to the new string
System.out.println(word.length());  // 4

The second line is a common mistake. It calls trim(), but nothing keeps the result, so word still refers to the string with spaces. The assignment fixes it: word now refers to the trimmed string. Notice what did change. The variable can be made to refer to another string; the string object itself never changes.

Chained calls

Because trim() returns a String, we can call another method on its result straight away. This is the same idea as the chained calls in Lecture 7, such as track.getArtist().equals(artist).

public String clean(String question)
{
    return question.trim().toLowerCase();
}

For the messy question, clean returns "how do i submit my work?". The calls run from left to right: first trim, then toLowerCase on the trimmed string.

Empty strings and line breaks

If someone sends only spaces, clean returns "", the empty string. It is a real String object with length 0. That is different from null, which means there is no object at all, so the bot can safely call isEmpty() on it:

public String replyTo(String question)
{
    String cleaned = clean(question);
    if(cleaned.isEmpty()) {
        return "Please type a question.";
    }
    return "Can you describe that in more detail?";
}

A reply sometimes needs two lines. Inside a string literal, \n is a line break. A long string can be split over two lines of code with +, which joins the pieces into one string:

String message = "Please check the course page.\n"
    + "Then post your question.";
System.out.println(message);

This prints Please check the course page. on one line and Then post your question. on the next. The line break in the source code does not matter; only the \n inside the string does.

5. Random

General replies

Back to the bot. Instead of one fixed reply, it keeps four general replies in an ArrayList<String> named generalReplies, always in this order. The constructor fills the list by calling a private helper, fillGeneralReplies(), and no method ever removes a reply.

IndexReply
0Can you describe that in more detail?
1Have you checked the course web page?
2That question comes up often. Let us look at it together.
3Please post that on the discussion board so others can see the answer.

To pick a reply we need a random index from 0 to 3. The class java.util.Random produces random numbers.

Creating a generator

Random is in java.util, so it needs an import. The bot creates one generator in its constructor and keeps it in a field:

import java.util.Random;           // above the class

private Random randomGenerator;    // a field in HelpBot

randomGenerator = new Random();    // in the HelpBot constructor

Every later call uses the same generator. Creating a new Random for each number is wasteful, and it is not what the class is designed for: one generator produces a whole sequence of numbers, one after another.

The numbers are pseudo-random. A fixed rule produces them, starting from a value called the seed. new Random() picks a different seed each run, so the numbers look unpredictable. new Random(42) always starts from the seed 42, so the program prints the same numbers every time it runs. We use a fixed seed in demonstrations, so everyone sees the same output.

The bound of nextInt

CallPossible results
randomGenerator.nextInt()any int, including negative ones
randomGenerator.nextInt(4)0, 1, 2 or 3
1 + randomGenerator.nextInt(6)1, 2, 3, 4, 5 or 6

nextInt(bound) returns a number from 0 up to bound - 1. The 0 is included; the bound itself is not. To get a number from 1 to n instead, add 1 to nextInt(n), as the die roll in the table does. The bound must be positive: nextInt(0) stops the program with an IllegalArgumentException.

Random list indices

The results of nextInt(list.size()) are 0 up to size - 1, which are exactly the valid indices of the list. So the index is always safe to pass to get, with one exception: for an empty list the bound is 0, and nextInt(0) fails. A method that might see an empty list must check for that before it calls nextInt.

The bot's list always holds four replies, so its method needs no check:

public String pickGeneralReply()
{
    int index = randomGenerator.nextInt(generalReplies.size());
    return generalReplies.get(index);
}

Picking a reply does not remove it, so the same reply can come up twice in a row. For a question that is not empty, replyTo now ends with return pickGeneralReply(); instead of the fixed reply.

6. Ratings

Primitive values and wrapper classes

After each reply, the user rates it from 1 to 5, and the bot keeps the ratings in a list. A rating is an int. But int is a primitive type: an int value is just a number, not an object. A collection such as ArrayList can only hold objects, so it cannot hold an int directly.

For each primitive type, java.lang has a wrapper class. An object of a wrapper class holds one primitive value.

Primitive typeWrapper class
intInteger
doubleDouble
booleanBoolean
charCharacter

The type in the angle brackets must be a class, so the ratings go in an ArrayList<Integer>. ArrayList<int> does not compile.

Autoboxing and unboxing

ArrayList<Integer> ratings = new ArrayList<>();
ratings.add(5);                 // autoboxing
int first = ratings.get(0);     // unboxing

add needs an Integer, but we pass the int 5. Java wraps the value in an Integer for us; this is called autoboxing. get(0) returns an Integer, but first is an int, so Java takes the value out again; this is unboxing. We write neither step, and the value never changes: first is 5. Integer and int are still different types. Only the Integer is an object.

Recording ratings

public void addRating(int rating)
{
    if(rating >= 1 && rating <= 5) {
        ratings.add(rating);
    }
}

After addRating(5), addRating(3) and addRating(4), the list holds three ratings. A rating outside 1 to 5 is ignored, so addRating(0) and addRating(6) add nothing. A second method, numberOfRatings(), returns ratings.size(); the list already knows its size, so no separate counter is needed.

Average rating

public int averageRating()
{
    if(ratings.isEmpty()) {
        return 0;
    }
    int total = 0;
    for(int rating : ratings) {
        total = total + rating;
    }
    return total / ratings.size();
}

The loop variable is an int, so each Integer in the list is unboxed as the loop reaches it. For the ratings 5, 3 and 4 the total grows to 5, then 8, then 12, and the average is 12 / 3 = 4. Both numbers are ints, so the division gives a whole number and drops any fraction. The empty check comes first because dividing by a size of 0 would stop the program.

7. Documentation

Javadoc comments

The library documentation is not written separately. It is made from special comments in the source code of each class, and we can document our own classes the same way. Another programmer, or we ourselves in three months, should be able to use the class from its documentation alone.

A documentation comment, or Javadoc comment, starts with /** (two asterisks) and ends with */. It goes just above the class or method it describes. An ordinary comment that starts with /* is ignored by the documentation tools. The class comment says what the class is for, and two tags give the author and the version:

/**
 * Answers course questions with a general reply and keeps
 * the ratings that users give.
 * @author Pranjal Patra
 * @version 1.0
 */
public class HelpBot

Method comments

A method comment starts with a sentence that says what the method does. Then each parameter gets an @param tag, with the parameter name and a description, and the result gets an @return tag. A void method and a constructor have no @return.

/**
 * Remove the spaces around a question and put it in lower case.
 * @param question The typed text; must not be null.
 * @return The cleaned text. The original string is unchanged.
 */
public String clean(String question)

A good comment says what a caller needs to know: what the method does, what it expects, and what it gives back. A comment that only repeats the method name, such as “Cleans the question”, adds nothing.

Information hiding

The ratings list is private, so other classes can only add to it through addRating. Every stored rating has therefore passed the check. If the list were public, another class could write bot.ratings.add(99), and the average would be wrong.

Keeping fields private is called information hiding. The public methods are the interface of HelpBot; the private fields and helpers, such as fillGeneralReplies, are its implementation. Because no other class can see the implementation, we can later change it, for example by storing the ratings in a different way, without changing any class that uses the bot. Private members still deserve comments, for the people who read and maintain the source.
