# COMP 2001 Workbooks

Interactive workbooks for **COMP 2001: Object-Oriented Programming**
(Memorial University). Code listings compile and run in the browser,
checkpoints and practice problems are checked as you work, and correct
answers earn XP that can be spent to reveal model answers. Java runs locally
in the page (CheerpJ in a Web Worker, with the Eclipse compiler); there is no
server and nothing is uploaded.

**Live site:** <https://pranjal-mun.github.io/comp2001workbooks/>

## Run locally

```bash
node tools/serve.mjs 9000
```

Then open <http://localhost:9000/>. The Java runtime is loaded from the
CheerpJ CDN and needs a server that supports byte-range requests, which is
why the small `tools/serve.mjs` is used instead of `python3 -m http.server`.
Add `?localAssets=1` to a page URL to use the pinned copy of CodeMirror in
`vendor/` instead of the CDN.

## Layout

```
index.html    landing page
workbooks/    one folder per lecture: index.html + exercises.json (+ build_exercises.py)
runtime/      shared engine: Java worker, grader, widgets, theme, fonts
runtime/java/ ecj.jar (Eclipse compiler) and workbook-runner.jar (the in-page runner)
tools/        check_workbook.py (verify a workbook), answers.py (base64 helper),
              build_runner.sh + runner/ (source of workbook-runner.jar), serve.mjs
vendor/       pinned CodeMirror for the offline fallback
```

## Writing a workbook

1. Write `workbooks/lecture-NN/build_exercises.py` and run it. It produces
   `exercises.json`; every example output and expected result is generated by
   compiling and running the code on the desktop JVM, never typed by hand.
2. Write `workbooks/lecture-NN/index.html` with the prose and the widget
   tags (`<wb-example>`, `<wb-exercise>`, `<wb-table>`, `<wb-short>`).
3. Verify with `python3 tools/check_workbook.py workbooks/lecture-NN`
   (needs `java` on the PATH). It runs the same runner class the page uses,
   so what passes here passes in the browser.
4. Set `built: true` for the lecture in `runtime/schedule.js`.

## When workbooks open

Lectures run Tuesday and Thursday from 2:00 to 3:15 p.m. A posted workbook
unlocks at 3:15 p.m. on the day of the lecture before it, so students can
start the next workbook as soon as class ends (a term test counts as the
lecture before). The first lecture's workbook opens when that lecture starts.
Until then the page shows when it opens. The schedule, lecture times, and
`opensAt` rule live in `runtime/schedule.js`.

Rebuild the runner after editing `tools/runner/workbook/Runner.java` with
`sh tools/build_runner.sh` (needs a JDK).

## Notes

- Press **F** on a workbook page to present it in class, one topic at a time.
- Progress and XP live in the browser's `localStorage`; the `⋯` menu exports
  and imports them as JSON.
- Programs compile with a Java 8 target. The first run on a page downloads
  the Java runtime (about 15 seconds); later runs take a second or two.
- The site is plain static files with relative paths; GitHub Pages serves the
  repository root (`.nojekyll` keeps `vendor/` untouched).
